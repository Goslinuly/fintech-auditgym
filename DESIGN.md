# DESIGN — auditgym

> Документ дизайна. Разделы 1–3 и 6 готовы; 4, 5, 7, 8 дописываются по мере готовности оценщика и политик (хакатон в процессе).

## 1. Устройство среды

См. [`docs/env.md`](docs/env.md): `AuditEnv(mode="train"|"eval").reset(seed, config) -> (obs, info)`, `.step(action) -> (obs, reward, terminated, truncated, info)`; 5 действий (`list_records`, `get_record`, `get_document`, `calculator`, `submit`), 100 шагов и 60 с на эпизод, каждое действие стоит 1 шаг, ограниченные ошибки без подсказок.
## 2. Генерация: скрытая история → документы → ошибки

См. [`docs/generator.md`](docs/generator.md#конвейер): история → чистый рендер + строгие инварианты → инъекция с записью причинных изменений → рендер → независимая проверка эталонным аудитором и достаточностью доказательств.
## 3. Канонические affected_ids и наборы доказательств по типам ошибок

См. [`docs/generator.md`](docs/generator.md#канонический-эталон-truthjson) — таблица правил по 4 типам и сценарии A/B.
## 4. Нормализация, допуски, tie-break в matcher

В работе. Сейчас действует упрощённый `StubGrader` (`auditgym/env/stub_grader.py`): trim + нижний регистр префикса таблицы, допуск `tolerance_minor` из эталона (1 для FX, 0 для остальных), жадное сопоставление. План — максимальное паросочетание с детерминированным tie-break (меньшая разница сумм → порядок вывода → issue_id).
## 5. Награда и метрики

`reward = clip(2·F1 − 1 − 0.002·inspection_steps, −1, 1)`; P/R/F1 по TP/FP/FN после сопоставления; пустой эталон + пустой ответ → F1 = 1; невалидный ответ → −1. Награда за исследование — 0, терминальная — только в `train`.
## 6. Изоляция и защита от утечек

См. [`docs/env.md`](docs/env.md#изоляция-и-защита-от-утечек): среда хранит только публичную часть эпизода; в `eval` эпизод генерируется и оценивается в отдельном процессе, откуда в среду приходят только публичные записи и оценка; данные отдаются копиями; leak-scan проверяет наблюдения, `info` и траектории.
## 7. Измеренный разбор сбоев базовых политик

Предварительные базовые результаты — в README (`python examples/baselines.py`).
## 8. Честные ограничения

* Награда не доказывает пригодность агента для реального аудита; модель на среде не обучалась.
* Только дебиторская сторона, фиксированные часовые пояса, без праздников (см. `docs/generator.md#ограничения`).
* Правила обнаружения открыты, поэтому агент, прочитавший все таблицы и применивший их, получает почти максимальную награду — сложность для LLM-агента в бюджете шагов и в точном выводе сумм и доказательств.
